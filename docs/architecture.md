# Architecture

The harness separates memory behavior from evaluation truth. Only fixture orchestration/scoring receive expectations; adapters and the mock receive public task/store values.

```text
Validated fictional suite -> virtual clock + runner -> independent ledger/oracles
                                    |                           |
                       Store put/delete/reopen                  |
                                    |                           |
                       Tenant-bound search/get                  |
                            |             |                     |
                       raw audit     retention filter -> mock selection
                            |                              |
                            +------ independent scorer <---+
                                         |
                                 stable reports/traces
```

| Module | Responsibility |
| --- | --- |
| model | Immutable Memory/Query/Answer/read values, Store protocol, virtual clock |
| suite | Bounded strict input validation, typed events, private expectations |
| store | SQLite persistence, tenant/ID keys, bound SQL, time predicates, tombstones |
| agent | Two-call tenant-bound reads, age filtering, four deterministic selections |
| scoring | Expected/observed scoring and ledger inspection without SQL/policy calls |
| runner | Fresh stores, actual close/reopen, evidence, summaries and comparison |
| api | Trusted adapter factory entry; no oracle argument to the backend |
| faults | Fixed fictional input bytes and deliberate read defects |
| __main__ | CLI validation/run/compare/fault routes and exit semantics |

Each scenario has a temporary on-disk database. The factory path uses an ordinal filename rather than a private scenario label. Reopen closes the adapter and constructs a new instance at the same path while retaining clock/ledger. Controls verify both forgotten/expired absence and useful persistent state. This is connection reopen, not crash/concurrent/distributed recovery.

The ledger tracks submitted records/deleted identities independently of persisted backend state. It never queries the adapter for expected truth. Every raw supported read is checked for tenant/deleted/expired/future, unknown or wrong-scope record, corrupt payload, and backend error. Hand-authored exact task/probe expectations measure utility; they are not generated by a policy.

Each mock task starts fresh with subject/key/description and tenant-bound tools, no suite/oracle/category/database handle. It makes search plus optional citation get and emits answer/unknown/conflict/error. This is code-level separation, not isolation from trusted Python introspection/editing.

Mandatory predicates belong to the reference adapter. Seven-day retention filters both tool paths after recording raw returns; the ledger still audits those raw records. Excluded IDs and delivered IDs make intentional horizon loss visible without masking a broken adapter. Retention affects utility, not the mandatory leak counters.

Comparison runs fresh stores against identical input/digest. Child failures and aggregate conjunction stay false even when analysis completes. Faults independently parse identical literal bytes for clean/broken runs; successful diagnosis never overrides failed benchmark behavior.

Canonical output omits timestamps, run IDs, temporary paths and elapsed-time scores. Runtime metadata remains. Reports are ordinary multi-file writes and can be partial after interruption; rerun in a fresh directory. Custom adapters execute synchronously in-process without a sandbox/time/resource cap. The verifier bounds only its generated CLI subprocesses to 30 seconds. There is no background service after completion.
